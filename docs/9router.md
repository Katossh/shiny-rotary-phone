# 9Router

9Router's Compose definition belongs to the separate
[Katossh/Docker](https://github.com/Katossh/Docker) repository. This NixOS
repository only integrates its lifecycle with the rootless Podman installation
already managed here; it does not copy Compose files or install Docker Engine.

## Repository prerequisite

Clone the Compose repository to the exact path expected by the Home Manager
user service:

```sh
gh repo clone Katossh/Docker ~/Docker
```

The 9Router stack is defined in `~/Docker/9router/compose.yaml`. Its launcher,
secret generation, and documentation are maintained in that repository.
The NixOS unit checks for `~/Docker/scripts/9router.sh`; when the repository
is absent, the unit is skipped instead of entering a failed state.

## Access

Open the dashboard at:

- http://127.0.0.1:20128

The published port is explicitly bound to loopback. The dashboard and API are
not exposed to the LAN. The OpenAI-compatible endpoint is:

- http://127.0.0.1:20128/v1

Create an API key in the dashboard and configure clients to use it as a Bearer
token. The Compose stack enforces API-key authentication for `/v1/*`.

The initial dashboard password and signing secrets are generated by
`~/Docker/scripts/init-secrets.sh` and persisted in
`~/Docker/.secrets/9router.env` with mode `0600`. Read the initial password
with:

```sh
sed -n 's/^INITIAL_PASSWORD=//p' ~/Docker/.secrets/9router.env
```

Change the dashboard password after first login. Do not remove that file while
keeping the 9Router data volume: it contains the original bootstrap password
and signing keys.

## Automatic startup

The Home Manager `9router.service` user unit starts the Compose stack through
rootless Podman. The workstation account has lingering enabled, so its user
systemd manager starts at boot without requiring an interactive login.

The container itself uses `restart: unless-stopped`; Podman's
`podman-restart.service` handles previously created containers during boot.
The Home Manager unit then runs the repository launcher to ensure the desired
Compose project is up.

## Management

```sh
systemctl --user status 9router.service
systemctl --user restart 9router.service
systemctl --user stop 9router.service
systemctl --user start 9router.service

# Logs and container status
cd ~/Docker
./scripts/9router.sh logs
./scripts/9router.sh ps
```

Stopping the systemd unit runs `podman compose down`. The named
`9router-data` volume is deliberately retained; it contains the database,
provider authorizations, and settings.

## Applying the NixOS integration

After the companion PR in `Katossh/Docker` is merged and the repository is
checked out at `~/Docker`, rebuild and test the configuration:

```sh
sudo nixos-rebuild test --flake .#workstation
systemctl --user status 9router.service
```

The Home Manager unit is declarative, but the Compose file, image version,
and local secrets remain owned by `Katossh/Docker`.
